# ADR-0005：服务端媒体处理默认，WASM 可选

- 状态：已接受（v0.0.1 架构草稿）
- 日期：2026-11-06

## 背景

复杂媒体预览、大文件上传和批量处理需要决定：默认在服务端还是浏览器完成；WASM 是否作为核心。

## 决策

- 默认服务端处理：
  - 元数据改写、ZIP 打包、EXR/TIFF/视频预览代理都在服务端。
  - `preview` 容器使用 ffmpeg/libvips/OpenImageIO。
- 浏览器 `wasm-client` 作为早期可选模块：
  - 客户端 ZIP（v0.0.1 只承诺 DOS mtime，不承诺内部元数据改写）；
  - 可选的本地预览转码（ffmpeg.wasm/WebCodecs）。
  - lazy load、feature flag、能力检测、失败回退服务端。
- 大文件上传用 tus/tusd，断点续传、批量队列；不走 WASM。
- 浏览器不默认承担媒体计算。

## 理由

- 8K EXR、长视频在浏览器解码/转码不现实。
- ffmpeg.wasm 体积大、需要 COOP/COEP、移动端内存压力大。
- 服务端预览可缓存、可限流、跨设备一致。
- WASM 仍有价值：本地隐私、离线、小文件快速预览、客户端 ZIP。
- 早期建立模块和契约，避免以后临时拼接。

## 代价

- 服务端 preview 镜像重、CPU/内存消耗大。
- 需要 pod 内独立 preview 容器和资源限制。
- WASM 客户端 ZIP 的元数据能力有限；完整元数据仍需服务端。
- 需要维护两套打包/预览路径的契约与测试。

## 替代方案

- 全部浏览器处理：服务端轻，但大文件/复杂格式不可行。
- 全部服务端：简单，但失去离线/本地隐私能力。
- 首版不提供 WASM：更简单，但与已确认路线冲突。
