# WebUI 主题与暗色模式

WebUI 需要同时支持亮色和暗色。默认跟随系统，用户可以手动选择，并且选择会被记住。

## 1. 三种模式

- `system`：跟随操作系统 `prefers-color-scheme`；
- `light`：强制亮色；
- `dark`：强制暗色。

不要只提供“亮/暗”二元开关；`system` 是默认值。

## 2. 为什么暗色不是“反色”

简单把白底黑字反过来会产生：

- 对比度不足；
- 状态色（成功/警告/错误）失真；
- 图片/视频颜色被反相；
- 焦点环、禁用态看不清；
- 阴影、边框、玻璃效果全部失效。

正确做法是建立语义化 design tokens：

```text
background
surface
surface-elevated
text-primary
text-secondary
border
accent
success / warning / danger
focus-ring
```

每个 token 在亮/暗主题下分别有值。组件只使用 token，不写死十六进制颜色。

## 3. 首屏无闪烁

主题选择要在 React 加载前应用：

- 在 HTML `<head>` 中读取持久化选择；
- 设置 `data-theme` 或 class；
- 再加载应用。

否则用户会先看到亮色闪一下，再切到暗色，体验很差。

## 4. 可访问性

- 正文对比度至少 WCAG AA；
- 焦点环在两种主题下都清晰；
- 错误/警告/成功状态不能只靠颜色区分；
- 禁用态仍要可辨认；
- 图表/缩略图/视频预览保持原色，不跟随主题反相；
- 透明通道用中性棋盘格，不用主题背景色。

## 5. 测试

- Playwright 分别跑 `light` 和 `dark`；
- 检查主题切换后刷新仍保持；
- 检查 `system` 跟随系统；
- 首屏无闪烁；
- 关键页面截图基线：上传、任务、预览、配置、管理；
- 对比度/焦点/禁用态检查。

## 6. 常见错误

- 只在根容器加一个暗色 class，内部组件仍有白底；
- 用 CSS `filter: invert()` 处理图片；
- 颜色写死在组件里；
- 主题切换后 toast/弹窗仍是旧主题；
- 暗色下阴影不可见；
- 忽略 `system` 模式。

## 7. 验收

暗色主题是 v0.0.1 的正式验收项，不是后续增强。每个新页面/组件都必须提供亮/暗两套验证。
