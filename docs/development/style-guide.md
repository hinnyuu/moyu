# 文档与 wiki 风格指南

## 1. 语言

- 以简体中文为主。
- 没有准确中文对应的术语、变量名、协议名、文件格式，保留英文。
- 第一次出现英文术语时，用一句通俗中文解释。
- 不写“压缩黑话”；假设读者是聪明但不熟悉本项目的人。

## 2. 三种文档的语气

### docs/

- 现在时；
- 准确、简洁、可执行；
- 描述“现在是什么”，不描述“怎么变成现在”。
- 例子：
  > `gateway` 只接受挂载证书，不支持通过 HTTP 上传私钥。

### history/

- 过去时；
- 记录时间、原因、影响、迁移、测试；
- 可以写“之前是……现在改为……”，但只在这里写。
- 例子：
  > 2026-11-06：决定网关使用 Rust，原因是 Rust WASM 已是确定路线，项目语言从 4 套收敛到 3 套。

### wiki/

- 教学语气；
- 面向人类，允许类比、图、示例、常见错误；
- 不写变更流水账；
- 可以链接 history 解释“为什么”，但正文保持当前状态。

## 3. 结构

每篇 docs 建议：

1. 目的/范围；
2. 概念；
3. 接口/配置；
4. 流程或状态机；
5. 失败模式；
6. 示例；
7. 相关链接。

每篇 wiki 建议：

1. 你会得到什么；
2. 前置条件；
3. 分步骤操作；
4. 验证方式；
5. 常见问题；
6. 相关 docs。

## 4. Markdown

- 一级标题只用于文档标题。
- 表格用于对比，不用于大段正文。
- 代码块标注语言。
- 图表优先 Mermaid；复杂拓扑可用 ASCII。
- 链接使用相对路径。
- 不写绝对主机路径；用 `/config`、`/data` 等约定路径。
- 端口示例用占位符或 `$PORT`，不要写死某个端口。

## 5. 术语

- `mtime` / `atime` / `ctime` / `btime`：第一次出现时解释。
- `DOS time`：ZIP 的 2 秒精度本地时间。
- `pod`：Podman/Kubernetes 中共享网络的一组容器。
- `image`：镜像模板；`container`：镜像的运行实例。
- `secret`：独立存放的敏感值，不进普通配置。

## 6. 禁止

- docs 中出现日期流水账、变更日志、旧实现叙述。
- history 中出现完整当前接口规范。
- wiki 中出现“本次发布/版本变更”。
- 为了过门禁写空话。
- 只给 agent 看的压缩短语；人类必须能读懂。

## 7. 示例

好：

> 解压 ZIP 会创建新的 inode，所以 `ctime`/`btime` 会变成解压时刻；ZIP 只携带 mtime。

不好：

> ZIP 洗时间，ctime 自动。

好：

> 如果当前是 bridge 网络，修改 `gateway.listen.port` 不会改变宿主端口；需要同时改 Quadlet 的 `PublishPort` 并重建 pod。

不好：

> 改端口要重启。

## 8. WebUI 视觉与主题

- 暗色主题是 v0.0.1 验收项，不是可选增强。
- 支持 `system` / `light` / `dark`；默认跟随系统，手动选择持久化。
- 首屏加载前应用主题，避免亮色闪烁。
- 使用语义化 design tokens：背景、表面、文字、边框、状态色、焦点色；组件内禁止散落硬编码颜色。
- 正文对比度至少 WCAG AA；焦点、错误、警告、禁用态在两种主题下都要清晰。
- 媒体预览保持原色，不随主题反相；透明区域使用中性棋盘格。
- 每个新页面/组件都必须有亮/暗两套验证。
